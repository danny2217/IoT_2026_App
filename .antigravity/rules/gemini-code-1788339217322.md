# ESP32 Dual-Core FreeRTOS & BLE Development Rules

## 1. Core Assignment & Concurrency
- **Core 0 (Protocol Core):** Exclusively handles BLE GATT Server (NimBLE), command queue processing (`g_cmd_queue`), and motor pulse generation.
- **Core 1 (Application Core):** Exclusively handles 100Hz ADC sensor acquisition and real-time respiration slope/phase detection.
- **Inter-Core IPC:** Never modify shared variables directly across cores without thread synchronization. Always use FreeRTOS Queues (`xQueueSend`, `xQueueReceive`) or atomic primitives.

## 2. NimBLE Callback Safety
- **No Blocking in Callbacks:** Never call hardware I/O, heavy computation, or long delays (`vTaskDelay`) inside `onWrite()` or `onConnect()`.
- **Producer-Consumer Pattern:** In `onWrite()`, parse packet headers (`0xAA 0x55`) and checksum, wrap valid commands into `Command` structs, and push to `g_cmd_queue`.

## 3. Signal Processing Pipeline
- **Raw Sensor Ingestion:** Do NOT apply redundant moving average filters if `breath_filter` / `breath_slope` are active. Pass pure raw ADC values directly into the filter engine to prevent phase lag.
- **Deterministic Timing:** Maintain 10ms sampling precision on Core 1 using `vTaskDelayUntil()`.

## 4. Fail-Safe Protocol
- If BLE disconnects (`onDisconnect`), immediately force motor control pin to `LOW` and reset runtime state to `STATE_IDLE`.
